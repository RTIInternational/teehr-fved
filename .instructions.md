## Workflow Design

### Main Flow Function

**Signature**:
```python
def ingest_nrcs_streamflow_forecasts_observations(
    temp_dir_path: Union[str, Path],
    end_dt: Union[str, datetime, pd.Timestamp, None] = None,
    num_lookback_days: Union[int, None] = DEFAULT_LOOKBACK_DAYS,  # 120 days
    start_spark_cluster: bool = False,
    location_ids: Union[str, list[str], None] = None,
) -> None
```

**Parameters**:
- `temp_dir_path`: Working directory for Spark and cache (required)
- `end_dt`: End of date window; defaults to current UTC date if None
- `num_lookback_days`: Lookback window (default 120 days); allows flexible date ranges
- `start_spark_cluster`: Whether to start Spark cluster (default False = local mode)
- `location_ids`: Override location filtering; if None, queries warehouse tables

**Execution Flow**:
1. Initialize Spark session and `RemoteReadWriteEvaluation` object
2. Compute date window from `end_dt` and `num_lookback_days`
3. Determine location IDs:
   - If `location_ids` provided: use directly
   - Otherwise: query warehouse for NRCS locations
4. Fetch observations and forecasts in parallel
5. Validate DataFrames against schema
6. Load to warehouse tables
7. Stop Spark session (in finally block)

### Task Functions

| Task | Purpose | Decorator | Timeout | Retries |
|------|---------|-----------|---------|---------|
| `_initialize_evaluation()` | Initialize Spark + Evaluation | `@task` | 5m | 2 |
| `_get_nrcs_locations_observed()` | Query location_id_aliases table | `@task` | 5m | 1 |
| `_get_nrcs_locations_forecast()` | Query location_crosswalks table | `@task` | 5m | 1 |
| `_fetch_nrcs_observations()` | Fetch observations from API | `@task(NO_CACHE)` | 15m | 2 |
| `_fetch_nrcs_forecasts()` | Fetch forecasts from API | `@task(NO_CACHE)` | 15m | 2 |
| `_validate_observations_dataframe()` | Validate obs schema | `@task(NO_CACHE)` | - | - |
| `_validate_forecasts_dataframe()` | Validate forecast schema | `@task(NO_CACHE)` | - | - |
| `_load_to_warehouse_primary()` | Load observations | `@task(NO_CACHE)` | - | - |
| `_load_to_warehouse_secondary()` | Load forecasts | `@task(NO_CACHE)` | - | - |

**Error Handling**:
- Fetch tasks retry 2x with 30s delay before failing
- Location query tasks retry 1x before warning (continue with empty list)
- Validation tasks fail immediately on schema mismatch
- Load tasks fail immediately on warehouse errors
- Spark session always stopped (try/finally pattern)

## Data Processing

### Input: NRCS AWDB API Responses

**Observations endpoint** (`/services/v1/data`):
- Element: `SRVO` (Snow Water Equivalent)
- Duration: `MONTHLY`
- Response structure: List of station payloads with monthly values
- Unit codes: `kac_ft` (thousands of acre-feet) or `ac_ft` (acre-feet)

**Forecasts endpoint** (`/services/v1/forecasts`):
- Element: `SRVO` (Snow Water Equivalent)
- Response structure: List of station payloads with forecast periods
- Data includes: `periodNormal` (mean) + `forecastValues` (ensemble members)
- Unit codes: `kac_ft` or `ac_ft`

### Output: Warehouse Schema

**Observations** → `primary_timeseries`:
```
location_id          | nrcs-09361500:CO:USGS
reference_time       | NaT (not applicable)
value_time           | 2026-01-01 (month start)
value                | 1000.0 (m³)
variable_name        | volume_monthly_sum
configuration_name   | nrcs_adjusted_observed
unit_name            | m^3
```

**Forecasts** → `secondary_timeseries`:
```
location_id          | nrcs-09361500:CO:USGS
reference_time       | 2026-10-15 (publication date)
value_time           | 2026-04-01 (forecast period start)
value                | 5000.0 (m³)
variable_name        | volume_amj_sum (Apr-Jun sum)
configuration_name   | nrcs_adjusted_forecast
unit_name            | m^3
member               | mean | 1 | 2 | ... (ensemble member)
```

### Unit Conversion

All values are converted to cubic meters (m³):
- `1 ac_ft` → 1,233.48 m³
- `1 kac_ft` → 1,233,481.84 m³

### Variable Filtering

Data is filtered to only include variables in `NRCS_VARIABLE_MAPPING`:
- Seasonal summed volumes: `volume_amjj_sum`, `volume_mjj_sum`, etc.
- Monthly summed volume: `volume_monthly_sum`
- Any other variables are logged as warnings and filtered out

## Location Filtering Strategy

### Observations (Primary Timeseries)

Query: `location_id_aliases` table with filter `location_id_alias LIKE 'nrcs-%'`

**Why**: NRCS data is stored as aliases in the warehouse. Observations are fetched using these aliases directly.

### Forecasts (Secondary Timeseries)

Query: `location_crosswalks` table with filter `secondary_location_id LIKE 'nrcs-%'`

**Why**: Forecasts cross-reference primary locations via crosswalk mappings. The NRCS secondary_location_id is used to fetch forecast data.

### Override Parameter

If `location_ids` parameter is provided (string or list), it is used for BOTH observations and forecasts, bypassing warehouse queries. Useful for:
- Testing with a small subset (e.g., single station)
- Manual re-ingestion of specific locations

## Date Window Handling

### Computation Logic

```python
if end_dt is None:
    end_dt = pd.Timestamp.utcnow().normalize()  # Today, UTC, 00:00

if num_lookback_days is None:
    start_dt = pd.Timestamp("1900-01-01")  # No limit
else:
    start_dt = end_dt - timedelta(days=num_lookback_days)

start_date_str = start_dt.strftime("%Y-%m-%d")  # YYYY-MM-DD format
end_date_str = end_dt.strftime("%Y-%m-%d")      # YYYY-MM-DD format
```

### Use Cases

**Monthly incremental update** (default):
```
end_dt=None, num_lookback_days=120
→ Fetches last ~4 months, captures monthly posting delays
```

**Initial backfill** (manual override):
```
end_dt="2025-10-01", num_lookback_days=1095
→ Fetches 3-year backfill from 2022-10-01 to 2025-10-01
```

**Fixed period**:
```
end_dt="2026-09-30", num_lookback_days=365
→ Fetches water year 2025-2026 (Oct 2025 – Sep 2026)
```

## Troubleshooting

### Symptom: "No NRCS locations found"

**Cause**: Warehouse tables (`location_id_aliases`, `location_crosswalks`) empty or no `nrcs-*` entries.

**Solution**:
- Verify warehouse is initialized and contains location data
- Override with explicit `location_ids` parameter for testing

### Symptom: "Failed to fetch observations/forecasts"

**Cause**: NRCS API unavailable, network error, or invalid location IDs.

**Solution**:
- Check NRCS AWDB API status: https://wcc.sc.egov.usda.gov/awdbRestApi/swagger-ui/index.html
- Verify location IDs format: `NNNNNNN:ST:SOURCE` (e.g., `09361500:CO:USGS`)
- Re-run workflow; task will retry 2x before failing

### Symptom: "DataFrame missing required columns"

**Cause**: API response structure changed or data not available for location.

**Solution**:
- Check NRCS API documentation for schema changes
- Review workflow logs for detailed error message
- Test with single known-good location first

### Symptom: "Warehouse load failed"

**Cause**: Schema mismatch, missing permissions, or warehouse unavailable.

**Solution**:
- Verify warehouse connection and credentials
- Check that `primary_timeseries` and `secondary_timeseries` tables exist
- Review Spark/Polaris connection settings in workflow environment
